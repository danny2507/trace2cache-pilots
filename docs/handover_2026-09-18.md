# Trace2Cache paired-runtime handover — 2026-09-18

## Bottom line

This release records a **negative but informative** paired-runtime repair study.  A frozen
`Qwen/Qwen2.5-1.5B-Instruct` receiver can consume eight continuous soft states emitted by a
small trace encoder, and decoder-facing supervision improves repair on the narrow paired
development task.  The current work does **not** establish task-disjoint program-repair
generalization, a benefit over textual traces, or direct KV-cache writing.

The strongest currently measured branch is the plain role-aware encoder trained with decoder
NLL + paired candidate ranking + 0.1 vector auxiliary.  It should be treated as a diagnostic
checkpoint, not as a release model for production repair.

## What the paired-runtime data tests

Every A/B record fixes the buggy Python source, public test, runtime events, actual output and
input bundle.  A and B differ only in supplied expected outputs and their truthfully derived
PASS/FAIL status; they require different patches.  The encoder receives neither behavior name,
family ID, target source nor patch label.  The receiver is frozen; its input marker is replaced
by eight continuous soft states.  This is normal soft-state prefill via `inputs_embeds`, **not**
a direct per-layer KV writer.

Data used for the main runs: 768 train pairs and 120 development pairs across 12 curated,
known toy-program families.  `test_short` has disjoint input bundles but the same families, so
it is evidence of new-bundle transfer only, not unseen-program generalization.

The selected plain decoder branch was expanded to all 120 development pairs: 170/240 true
repairs (70.83%), 60/120 complete pairs, and 46/240 paired-swap intended repairs (19.17%).
This panel was used for branch selection and contains known source families; it is not a final

11/24 true and 6/24 swapped repairs (20.83 pp); typed values had 13/24 true and 8/24 swapped
repairs (also 20.83 pp).  Thus typed values added generic repair behavior, not stronger causal
selection.

## Negative architecture controls

`typed_values.py` adds generic value/type/order nodes.  `binding_encoder.py` adds only audited
topology: `NEXT`, `SAME_SOURCE`, and `LAST_OBSERVED_VALUE`.  The latter is deliberately not
called a dynamic def-use/causal edge: it means an earlier event was the last callback snapshot
where a local variable's tagged value changed.  Variable spellings are never encoded.

Both typed and relation residual modules are zero-initialized so a warm-start initially matches
the pre-architecture encoder exactly.  The controls above show that neither richer raw value
fields, these relations, nor the added counterfactual loss improved paired repair.  Do not scale
them to held-out/full evaluation without a new predeclared reason.

## Release contents

The Hugging Face release contains only trainable/checkpoint state, raw result artifacts, this
handover and checksums.  It excludes base Qwen weights, runtime datasets, feature caches,
credentials and optimizer/model-cache directories.  The checkpoint files are PyTorch `.pt`
payloads containing the trace encoder state, oracle-code metadata, config and metrics; load
them only with the matching code revision.  They are not standalone Transformer models.

Useful files:

- `checkpoints/alignment_decoder200_seed401.pt`: strongest paired decoder diagnostic branch.
- `checkpoints/full_data_vector2000_seed401.pt`: common warm-start used by the forks.
- `artifacts/*`: machine-readable train and repair summaries/rows.
- `reports/decoder_alignment_control_2026-09-17.md`: detailed protocol and all controls.

## Reproduce

Use the project-local `.venv` and cached frozen receiver.  No API data generation is needed.

```bash
PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True .venv/bin/python \
  scripts/train_paired_trace_encoder.py \
  --dataset .local/datasets/paired_runtime_v2/train.jsonl \
  --validation-dataset .local/datasets/paired_runtime_v2/dev.jsonl \
  --init-checkpoint checkpoints/paired_runtime_v2/full_data_vector2000_seed401.pt \
  --objective decoder --sampling paired_family --steps 200 \
  --batch-size 16 --gradient-accumulation 8 --learning-rate 3e-5 --seed 401
```

Run `scripts/evaluate_paired_trace_encoder.py` with `true_latent paired_swap` and validate
generated patches against hidden tests.  See `docs/decoder_alignment_control_2026-09-17.md` for
exact commands, result hashes and the decision rule.

## Next justified step

The existing encoder/decoder modifications plateaued.  Before direct KV writing or broad
benchmark claims, build a transferable behavioral-delta bottleneck with explicit runtime
reconstruction probes, then test it on genuinely task-disjoint mutated MBPP with hidden tests,
evidence corruptions, multiple seeds and cluster confidence intervals.
